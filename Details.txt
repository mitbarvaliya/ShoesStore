- Product management (Shoes)
- Shopping cart functionality
- Order management

                         3. CONTROLLERS EXPLANATION

AdminController.php
--------------------
Purpose: Handles admin authentication and dashboard access

Methods:
- showLoginForm()     : Displays admin login form
- login()             : Validates admin credentials (username: "mit", password: "meet@3895")
- dashboard()         : Shows admin dashboard (requires session login)
- logout()            : Logs out admin and clears session

Security: Uses session-based authentication (not Laravel auth)

AdminOrderController.php
------------------------
Purpose: Manages orders from admin side

Methods:
- index()             : Shows all pending orders with pagination
- show($id)           : Shows detailed order information
- completedOrders()   : Shows all completed orders
- updateStatus()      : Updates order status (pending/completed)

Admin can mark orders as "completed" which affects cart/order workflow

ShoeController.php
------------------
Purpose: CRUD operations for shoe products

Methods:
- index()             : List all shoes (paginated)
- create()            : Show create shoe form
- store()            : Save new shoe to database
- show()             : Show single shoe details
- edit()             : Show edit shoe form
- update()           : Update shoe details
- destroy()          : Delete shoe (also removes image file)

Features:
- Image upload to public/shoes folder
- Best seller flag
- Soft deletes support

CartController.php
------------------
Purpose: Shopping cart management for users

Methods:
- add(Request, Shoe) : Add shoe to cart (increments qty if exists)
- index()            : Display cart with all items and total
- remove(Cart)       : Remove item from cart
- updateQuantity()   : Increase/decrease quantity (deletes if qty < 1)

Key Logic:
- If shoe already in cart, increments quantity by 1
- Calculates total price dynamically
- Only allows users to modify their own cart items

CheckoutController.php
----------------------
Purpose: Process orders from cart

Methods:
- index()            : Show checkout page with cart items
- store()           : Create order from cart items

Process:
1. Validates customer info (name, phone, address)
2. Creates Order record
3. Creates OrderItem for each cart item
4. Clears user's cart after order

OrderController.php
-------------------
Purpose: User order management

Methods:
- myOrders()        : Display user's order history
- cancelOrder()     : Cancel pending orders

HomeController.php
-----------------
Purpose: General pages

Methods:
- index()           : Home/welcome page
- shop()            : Product listing page
- contact()         : Contact form
- contactSubmit()   : Handle contact form submission
- about()           : About page

================================================================================
                         4. MODELS EXPLANATION
================================================================================

User.php
--------
Purpose: Represents registered users (customers)

Relationships:
- carts()           : HasMany - user's shopping cart items
- orders()          : HasMany - user's placed orders

Fields: id, name, email, password, email_verified_at, remember_token, timestamps

Shoe.php
--------
Purpose: Represents products (shoes)

Features:
- Uses SoftDeletes trait for soft delete functionality

Relationships:
- carts()           : HasMany - cart items containing this shoe
- orderItems()      : HasMany - order items containing this shoe

Fields: id, name, category, price, deleted_price, image, best_seller, timestamps, deleted_at

Cart.php
--------
Purpose: Represents items in user's shopping cart

Relationships:
- user()            : BelongsTo - cart item belongs to a user
- shoe()            : BelongsTo - cart item contains a shoe

Fields: id, user_id (FK), shoe_id (FK), quantity, timestamps

Order.php
---------
Purpose: Represents a placed order

Relationships:
- user()            : BelongsTo - order belongs to a user
- orderItems()      : HasMany - items in this order

Fields: id, user_id (FK), customer_name, phone, address, total_price, status (pending/completed/cancelled), timestamps

OrderItem.php
-------------
Purpose: Represents individual items in an order

Relationships:
- order()           : BelongsTo - item belongs to an order
- shoe()            : BelongsTo - item is a specific shoe

Fields: id, order_id ( (FK), quantity, price, timestampsFK), shoe_id

              6. PRIMARY KEYS & FOREIGN KEYS EXPLANATION
================================================================================

PRIMARY KEYS (PK)
=================

Each table has a primary key named 'id':
- users.id         : BIGINT UNSIGNED, AUTO_INCREMENT
- shoes.id         : BIGINT UNSIGNED, AUTO_INCREMENT  
- carts.id         : BIGINT UNSIGNED, AUTO_INCREMENT
- orders.id        : BIGINT UNSIGNED, AUTO_INCREMENT
- order_items.id   : BIGINT UNSIGNED, AUTO_INCREMENT

The primary key uniquely identifies each record in a table.

FOREIGN KEYS (FK)
==================

1. carts table:
   - user_id -> users.id (ON DELETE CASCADE)
     * When a user is deleted, all their cart items are automatically deleted
   - shoe_id -> shoes.id (ON DELETE CASCADE)
     * When a shoe is deleted, cart items containing it are deleted

2. orders table:
   - user_id -> users.id (ON DELETE CASCADE)
     * When a user is deleted, all their orders are automatically deleted

3. order_items table:
   - order_id -> orders.id (ON DELETE CASCADE)
     * When an order is deleted, all its items are automatically deleted
   - shoe_id -> shoes.id (ON DELETE CASCADE)
     * When a shoe is deleted, order items containing it are deleted

RELATIONSHIP DIAGRAM
====================

users (1) --------< (N) carts (N) >-------- (1) shoes
     |
     |
     v
  (1) --------< (N) orders (1) >--------< (N) order_items (N) >-------- (1) shoes

One User can have Many Cart items
One User can have Many Orders
One Order has Many OrderItems
One Shoe can be in Many Carts and Many OrderItems

              8. ADMIN SIDE CART SECTION - COMPLETE WORKFLOW
================================================================================

UNDERSTANDING THE CART IN THIS APPLICATION
==========================================

In this Laravel shoe store application, the "cart" is managed on the USER side.
The ADMIN does not directly manage carts. Here's how it works:

CART WORKFLOW (User Side)
==========================

1. ADD TO CART (CartController::add)
   - User clicks "Add to Cart" on a shoe
   - System checks if user already has that shoe in cart
   - IF EXISTS: Increment quantity by 1
   - IF NOT EXISTS: Create new cart entry with quantity 1
   - Redirect to cart page with success message

2. VIEW CART (CartController::index)
   - Fetch all cart items for logged-in user
   - Load associated shoe data using eager loading
   - Calculate total: SUM(shoe_price * quantity) for each item
   - Display cart view with items and total

3. UPDATE QUANTITY (CartController::updateQuantity)
   - User clicks +/- buttons
   - IF increase: quantity + 1
   - IF decrease: 
     * If quantity > 1: quantity - 1
     * If quantity = 1: Delete cart item entirely
   - Save changes and redirect back

4. REMOVE ITEM (CartController::remove)
   - User clicks remove/delete button
   - Verify cart belongs to current user
   - Delete cart entry
   - Redirect back with success message

5. CHECKOUT (CheckoutController)
   - User fills customer details (name, phone, address)
   - System creates Order record
   - For each cart item, creates OrderItem record
   - Deletes all cart items for user
   - Order status defaults to "pending"

6. ORDER COMPLETION (AdminOrderController)
   - Admin views pending orders
   - Admin clicks "Complete Order" 
   - Order status changes from "pending" to "completed"
   - Order is moved to completed orders view

ADMIN DASHBOARD CART STATISTICS
================================

In admin/dashboard.blade.php:
- Shows "Total Cart Items" count from Cart model
- This displays how many items are currently in ALL users' carts
- Helps admin understand cart activity

KEY RELATIONSHIPS IN CART SYSTEM
=================================

- User -> hasMany -> Cart (one user can have multiple cart items)
- Shoe -> hasMany -> Cart (one shoe can be in multiple carts)
- Cart -> belongsTo -> User
- Cart -> belongsTo -> Shoe

When user places order:
- Cart items are converted to OrderItems
- Cart items are deleted (cart becomes empty)
- Order is created with pending status
- Admin can then manage the order
